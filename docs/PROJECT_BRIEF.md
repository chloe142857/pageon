# 수학 종이 활동지 평가 웹앱 — Codex 기준 문서

> 상태: 제품 요구사항과 개발 순서의 기준 문서. 실제 저장소 구조·기술 선택·DB 상세 설계는 Codex가 저장소를 조사한 뒤 별도 설계 문서에 기록한다. 이 문서와 기존 코드가 충돌하면 임의로 교체하지 말고 차이를 보고하고 결정안을 제안한다.

## 1. 제품 목표

초등 수학 수업에서 학생이 **종이 활동지에 연필로 풀이**하고 모바일·태블릿 웹브라우저로 촬영해 제출하면, 시스템이 문항별 결과를 처리하고 성취기준별 학습 기록을 누적한다. 교사는 PC에서 활동지를 만들고 인쇄하며, 제출·검토·분석을 관리한다. 별도 학생 앱이나 학생 이메일 계정은 요구하지 않는다.

핵심 흐름: 교사 활동지 생성·확정 → 구조화된 문항 데이터와 PDF·QR 생성 → 학생 종이 풀이 → QR 접속 및 인증 → 여러 페이지 촬영·제출 → 원본 보존 및 이미지 처리 → 답안 인식·채점 → 필요한 답안만 교사 검토 → 최종 결과와 분석.

## 2. 반드시 지킬 제품 원칙

1. 교사의 반복 입력을 최소화한다. 문항 유형에서 기본 채점 전략을 정하고 AI가 먼저 제안한다. 교사는 확인하고 필요한 경우 수정한다.
2. AI 인식 결과, AI 채점 제안, 최종 확정 결과를 구분해 저장한다. 자동 확정도 교사가 변경할 수 있다.
3. 학생의 필기 **원본 이미지**를 보존하고 교사가 실제 답안을 볼 수 있어야 한다. 보정본과 문항별 이미지도 별도로 보관한다.
4. 학생 분석은 성취기준별 최근 성과, 시간에 따른 변화, 반복 오류와 최근 오답을 우선한다. 모든 활동지의 단순 전체 평균을 대표 지표로 사용하지 않는다.
5. 동일 활동지를 푼 학급의 활동지별 평균·중앙값·분포·문항별 정답률·미제출 현황은 중요하다.
6. QR은 활동지만 식별하며 학생 개인정보를 포함하지 않는다. 학생 신원은 인증된 세션에서 결정한다.
7. 활동지는 여러 페이지를 지원한다. AI가 추천한 성취기준·문항 위치·채점 결과는 교사가 수정할 수 있다.
8. 학생 인증과 데이터 접근 권한을 서버에서 검증한다. PIN을 평문 저장하거나 클라이언트에 관리자 권한을 노출하지 않는다.

## 3. 사용자와 주요 화면

| 사용자 | 기기 | 주요 화면 |
| --- | --- | --- |
| 교사 | PC | 홈, 학급·학생, 활동지 생성·편집·상세, 제출 현황, 답안 검토, 학급·성취기준 분석, 학생 상세 |
| 학생 | 모바일·태블릿 웹 | 학급 코드·학생 식별자·PIN 인증, QR 활동지 진입, 페이지별 촬영·재촬영, 전체 사진 확인, 제출 완료 |

교사 활동지 상세는 활동지·제출현황·문항분석·성취기준의 정보에 접근할 수 있어야 한다. 검토 화면은 **검토해야 할 답안 단위**로 나열한다. 한 화면에 학생, 문항, 원본 필기 이미지, 인식 답안, 정답, AI 판정, 인식·채점 신뢰도, 짧은 판단 근거와 교사 수정 동작을 보여준다.

학생 촬영 화면은 기본적으로 후면 카메라를 시도하고 전·후면 전환, 실시간 미리보기, 촬영, 페이지 표시, 개별 재촬영, 최종 썸네일 확인을 제공한다. 브라우저 권한·기기 제약에 따른 대체 입력 수단도 설계 단계에서 검토한다.

## 5. 기술 방향과 경계

- 후보: 하나의 Next.js + TypeScript 웹앱과 Supabase PostgreSQL·Auth·Storage·RLS. **기존 저장소가 있으면 먼저 조사하고 기존 선택을 존중한다.** 기술 교체는 근거와 영향을 제안한 뒤 결정한다.
- 브라우저는 화면 표시·촬영·재촬영·업로드를 담당한다. 인증 검증, 권한 적용, AI 호출, PDF 분석, 이미지 처리, 채점, 최종 집계는 신뢰할 수 있는 서버 측에서 처리한다.
- 시간이 오래 걸리는 이미지 처리·OCR·AI 채점은 백그라운드 작업과 재시도·상태 기록을 고려한다. 요청 하나에 모든 단계를 묶어 타임아웃에 의존하지 않는다.
- 활동지 PDF, 원본 촬영본, 보정본, 문항별 답안 이미지는 비공개 파일 저장소에 둔다. DB에는 파일 경로, 소유 관계, 처리 상태·버전과 메타데이터를 기록한다. 보호되지 않는 공개 URL로 학생 답안을 노출하지 않는다.
- 초기에 정답 인식과 채점 처리는 교체 가능한 단순 경계로 두고, 실제 OCR 공급자·수식 인식·서술형 판정은 성능을 검증하며 연결한다. 과도한 범용 프레임워크는 만들지 않는다.

## 6. 핵심 데이터 개념

다음 개체의 관계와 권한을 저장소 조사 후 설계한다: Teacher, Classroom, Student, Curriculum, AchievementStandard, Unit, Worksheet, WorksheetPage, Question, Submission, SubmissionPage, StudentAnswer, AIRecognitionResult, AIGradingResult, FinalGradingResult.

- 활동지와 문항 각각 여러 성취기준에 연결될 수 있다. 학년·학기·교과·영역·단원·차시·차시 목표를 지원한다.
- 생성 활동지는 PDF와 **동일 버전의 구조화된 문항 데이터**를 저장한다. 문항 ID, 유형, 정답·허용 표현, 설명, 배점, 페이지, 문항·답안 영역 좌표, 성취기준을 연결한다. PDF 편집으로 위치가 바뀌면 좌표도 함께 갱신한다.
- 제출은 학생·활동지 버전·촬영 페이지·처리 상태와 연결한다. 재제출 정책과 중복 제출 처리는 설계 문서에서 명시한다.
- 문항별 답안은 이미지, 인식 텍스트/수식, 인식 신뢰도, AI 채점 제안과 채점 신뢰도, 검토 상태, 최종 판정·점수·확정 주체·시각을 구분한다.
- 채점 분류: correct, partial, incorrect, unreadable, teacher_review_required. 확정 상태: AUTO_CONFIRMED, REVIEW_REQUIRED, TEACHER_CONFIRMED. 부분점수와 배점의 관계는 구현 전 정의한다.
- 통계는 **최종 확정 결과**를 기준으로 하며, 검토 대기 답안을 어떻게 표시·집계할지 명시한다.

## 7. 인식·채점 원칙과 기술 위험

| 문항 유형 | 초기 처리 | 검토가 필요한 경우 |
| --- | --- | --- |
| multiple_choice | 선택값과 정답 정확히 비교 | 표기 중복·읽기 실패·낮은 인식 신뢰도 |
| short_answer | 문자·단위 등 문항별 허용 규칙에 따라 정규화 후 비교 | 애매한 필기·허용 표현 불명확 |
| calculation | 숫자·수식 인식 후 안전한 동치 규칙 적용 | 수식 구조 불확실·풀이 과정 평가 필요 |
| constructed_response | 모범답안, 필수 개념, 허용 표현을 참고해 AI가 제안 | 부분정답·의미 판정 모호·낮은 채점 신뢰도 |

인식 신뢰도와 채점 신뢰도를 별도로 저장한다. 신뢰도 임계값은 실제 학생 필기 샘플로 검증해 결정한다. 낮은 신뢰도와 부분정답 가능성은 검토 대기로 보내고, 모든 답안을 검토 대기로 보내지 않는다.

특히 **촬영 문서의 가장자리 탐지·원근/회전/기울기·조명/그림자/흐림 보정, 템플릿 정렬, 문항 영역 좌표 오차, 손글씨 숫자·수식 인식, 서술형 판정**은 정확도 위험이 크다. 완전 자동화를 가정하지 말고 실제 인쇄물·실기기·실제 필기에서 성공률과 실패 유형을 측정한다. 원본을 유지하며 오정렬과 인식 실패 시 교사가 답안을 확인할 수 있게 한다.

## 8. 단계별 구현 순서

| Phase | 범위 | 완료 기준·검증 |
| --- | --- | --- |
| 1. 기반 | 교사 인증, 학급·학생 관리, 학급 코드·학생 식별자·PIN, 교사/학생 경로, 기본 권한·DB | 교사가 학급·학생을 등록하고 학생이 로그인. 권한 분리 확인 |
| 2. 활동지 | 교육과정·성취기준, AI 생성, 구조화된 문항, 미리보기·편집, 인쇄 PDF·QR | 교사가 실제 PDF를 출력하고 QR로 해당 활동지에 접근. PDF와 문항 데이터 일치 확인 |
| 3. 제출 | QR 인증 복귀, 모바일 카메라, 전·후면 전환, 여러 페이지, 개별 재촬영, 원본 업로드 | 실물 3페이지를 스마트폰·태블릿에서 제출. 실제 기기와 권한·재시도 확인 |
| 4. 처리·인식 | 문서 보정, 템플릿 정렬, 문항 영역 추출, OCR·수식 인식, 인식 신뢰도 | 실제 필기에서 문항별 이미지와 인식 결과를 교사가 대조. 실패 유형 기록 |
| 5. 채점·검토 | 유형별 채점, AI 제안, 이중 신뢰도, 자동 확정/검토 대기, 교사 확정·수정 | 필요한 답안만 큐에 나타나고 최종 결과가 AI 결과와 별도로 저장 |
| 6. 분석 | 제출·미제출, 활동지 평균·중앙값·분포, 문항 정답률, 성취기준·학생 변화 | 학급 → 활동지·문항 → 성취기준·학생으로 확인 가능. 최종 결과 기준 검증 |
| 7. 기존 PDF | PDF 분석·문항/영역 추정·교육과정 추천, 교사 확인·정답 설정, 기존 파이프라인 재사용 | 기존 PDF 하나가 QR 제출→인식→채점 흐름을 통과 |

초기에는 AI/OCR 처리의 응답을 명확히 표시한 목 데이터로 대체해 앞 단계의 사용자 흐름을 검증할 수 있다. 목 결과를 실제 인식·채점 성능으로 표현하지 않는다. 각 Phase의 기능이 실제로 동작해야 다음 단계로 넘어간다.

## 9. 작업 방식

각 Phase는 현재 저장소와 이전 Phase 결과를 확인한 뒤 해당 범위만 구현한다. 변경 파일·DB migration·실행/테스트 결과·남은 문제를 보고한다.
